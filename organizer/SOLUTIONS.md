## Setup

### Platform

Use a free CTF platform such as [CTFd](https://ctfd.io/) (self-hosted with Docker in ~5 minutes) or a hosted option like [rCTF](https://rctf.redpwn.net/). Create one challenge per folder, paste the description from each challenge's `README.md`, attach the files from its `files/` folder, and configure the hints with the listed point costs.

```bash
git clone https://github.com/CTFd/CTFd.git && cd CTFd
docker compose up -d   # then open http://localhost:8000
```

### Hosting challenge 01 (optional)

Students can open `index.html` locally, but hosting it feels more realistic:

```bash
cd challenges/01-inspect-the-oasis/files
python3 -m http.server 8080
```

### Changing the flags

All handout files are generated by `organizer/build_handouts.py`. To change any flag (recommended if you reuse this CTF), edit the `FLAGS` dictionary and run:

```bash
python3 organizer/build_handouts.py
```

The script regenerates challenges 01, 06–20, and prints the new text for challenges 02, 03, 04, and 05. Paste those printed values into the matching challenge `README.md` files.

Challenges 14, 17, and 18 need the `zip`, `gcc`, and `git` command-line tools. If `gcc` is missing, the existing `floodgate` binary is kept. The compiled binary is Linux x86-64, so tell students on Windows or macOS to use WSL, a Linux VM, or a decompiler only.

After regenerating, confirm that challenges 11–20 are still solvable from the handout files alone (about 30 seconds, most of it the ZIP brute-force):

```bash
python3 organizer/verify_solutions.py
```

If you change `FLAGS["vigenere_key"]` or `FLAGS["jwt_secret"]`, update the matching hints in challenges 13 and 20.

### Recommended timing

- **Duration:** 3–4 hours for challenges 01–10 only; 5–6 hours with all 20.
- **Last 30 minutes:** walk through solutions on the projector. This is where most of the learning happens.

## Walkthroughs

### 01 — Inspect the Oasis (Web)

The flag is split across the three website files as developer comments.

1. Right-click → **View Page Source** on `index.html`: `<!-- ... Part 1/3 of the flag: TAIBAH{1nsp3ct_ -->`
2. Open `style.css`: `/* Part 2/3 of the flag: th3_ */`
3. Open `script.js`: `// Part 3/3 of the flag: s0urc3}`

**Lesson:** Anything sent to the browser is visible to the user. Never put secrets in client-side code.

### 02 — Strange Letters (Encoding)

```bash
echo "VEFJQkFIe2I0czM2NF8xc19uMHRfM25jcnlwdDEwbn0=" | base64 -d
```

**Lesson:** Base64 is an encoding, not encryption. It provides zero confidentiality.

### 03 — Julius in the Desert (Cryptography)

`T → W` is a shift of 3. Shift every letter back by 3 (numbers and symbols unchanged):

```bash
echo 'WDLEDK{mx11xv_z0xog_e3_su0xg}' | tr 'D-ZA-Cd-za-c' 'A-Za-z'
```

**Lesson:** Classic ciphers have tiny keyspaces (25 possible shifts) and fall to brute force or known-plaintext attacks.

### 04 — Ones and Zeros (Encoding)

Each 8-bit group is one ASCII character. CyberChef → **From Binary**, or:

```python
bits = "01010100 01000001 ..."
print("".join(chr(int(b, 2)) for b in bits.split()))
```

### 05 — Crack the Falcon (Password Cracking)

32 hex characters means MD5. Paste the hash into [CrackStation](https://crackstation.net/) → `falcon`. Or:

```bash
john --format=raw-md5 --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
```

**Flag:** `TAIBAH{falcon}`

**Lesson:** Unsalted fast hashes (MD5, SHA1) are cracked instantly for common passwords. Use bcrypt/Argon2 with salts.

### 06 — Desert Picture (Forensics)

The flag is stored in a PNG `tEXt` metadata chunk.

```bash
strings desert.png | grep TAIBAH
# or
exiftool desert.png
```

**Lesson:** Files carry metadata (camera model, GPS location, comments). Always check it during investigations, and strip it before sharing sensitive photos.

### 07 — Not a PDF (Forensics)

```bash
file report.pdf
# report.pdf: Zip archive data ...
mv report.pdf report.zip
unzip report.zip
cat report/flag.txt
```

The file starts with `PK` (`50 4B 03 04`), the ZIP signature. The content is compressed, so `strings` alone does **not** reveal the flag. Students must identify the real file type.

**Lesson:** File extensions can lie; magic bytes tell the truth. Attackers use this to disguise malware.

### 08 — Camel Caravan (Linux)

```bash
tar -xzf caravan.tar.gz
find caravan -name "*flag*"
# caravan/day2/flag.txt              <- decoy ("Nope, not this one")
# caravan/day3/tent/.secret/.flag.txt
cat caravan/day3/tent/.secret/.flag.txt
```

**Lesson:** Files starting with `.` are hidden from `ls`. Use `ls -la` and `find`.

### 09 — Password Checker (Reverse Engineering)

Each character is XORed with `KEY = 42` and compared to `SECRET`. XOR is reversible:

```python
SECRET = [...]  # copy from checker.py
KEY = 42
print("".join(chr(c ^ KEY) for c in SECRET))
```

**Lesson:** Client-side or hardcoded password checks can always be reversed. Obfuscation is not security.

### 10 — Who Broke In? (Log Analysis)

```bash
grep "Failed password" auth.log | grep -oE "from [0-9.]+" | sort | uniq -c | sort -rn | head -3
#    312 from 203.0.113.66     <- attacker
#     17 from 192.0.2.14
#     17 from 10.0.0.31

grep "Accepted password" auth.log | grep 203.0.113.66
# Sep 24 11:10:18 taibah-srv sshd[...]: Accepted password for webadmin from 203.0.113.66 ...
```

312 failed attempts in about 10 minutes followed by one successful login.

**Flag:** `TAIBAH{203.0.113.66_webadmin}`

**Lesson:** Brute-force attacks are loud in logs. Defenses include SSH keys, disabling password auth, fail2ban, and MFA.

> Note: All IP addresses in the log come from the reserved documentation ranges (RFC 5737) or private ranges, so they don't belong to any real person or organization.

### 11 — Sandstorm XOR (Cryptography)

Known-plaintext attack. XOR the first 7 ciphertext bytes with `TAIBAH{`:

```python
ct = bytes.fromhex(open("cipher.hex").read().strip())
print(bytes(a ^ b for a, b in zip(ct, b"TAIBAH{")))   # b'DUNE5DU' -> key is "DUNE5"
key = b"DUNE5"
print(bytes(b ^ key[i % len(key)] for i, b in enumerate(ct)).decode())
```

Plaintext: `TAIBAH{x0r_w1th_4_sh0rt_k3y_1s_w34k} -- Meet me at the old well after sunset. Come alone.`

**Lesson:** Repeating-key XOR falls apart as soon as the attacker knows or guesses a few plaintext bytes. File headers, greetings, and flag formats are all known plaintext.

### 12 — Close Primes (Cryptography)

`q` is the next prime after `p`, so `|p - q|` is tiny compared to `n`. Fermat's method factors it in one or two iterations:

```python
import math
n, e, c = ...  # from public.txt
a = math.isqrt(n) + 1
while not math.isqrt(a*a - n) ** 2 == a*a - n:
    a += 1
b = math.isqrt(a*a - n)
p, q = a - b, a + b
d = pow(e, -1, (p - 1) * (q - 1))
m = pow(c, d, n)
print(m.to_bytes((m.bit_length() + 7) // 8, "big"))
```

[RsaCtfTool](https://github.com/RsaCtfTool/RsaCtfTool) also solves it: `RsaCtfTool -n <n> -e 65537 --decrypt <c> --attack fermat`.

**Lesson:** RSA's strength depends on *how* the primes are chosen, not just their size. Use a vetted library, never a home-made key generator.

### 13 — The Merchant's Letter (Cryptography)

Vigenère with key **`MIRAGE`**. Only ASCII letters are shifted, and the key advances only on letters.

- **Automatic:** paste `letter.txt` into [dCode's Vigenère solver](https://www.dcode.fr/vigenere-cipher) and choose automatic decryption. The index of coincidence peaks clearly at key length 6.
- **Known plaintext:** the encrypted flag line starts with `ZEUJRH`. Subtracting `TAIBAH` gives `GEMIRA`, which is `MIRAGE` rotated, because the flag doesn't start on a key boundary. Students who try `GEMIRA` on the whole letter get garbage and must realize the key's starting point is shifted.
- CyberChef: **Vigenère Decode**, key `MIRAGE`.

**Lesson:** Polyalphabetic ciphers hide single-letter frequencies, but repeating keys still leak statistics (Kasiski examination, index of coincidence).

### 14 — Locked Vault (Password Cracking)

The PIN is **`739214`**. There are only 10⁶ possible PINs.

```bash
zip2john vault.zip > vault.hash
john --mask='?d?d?d?d?d?d' vault.hash      # instant
unzip -P 739214 vault.zip && cat flag.txt
```

A pure-Python loop with `zipfile` takes about 30 seconds. About 1 in 256 wrong PINs passes ZipCrypto's quick header check and only fails on decompression or CRC, so students must catch *all* exceptions, not only `RuntimeError`.

**Lesson:** Short numeric PINs are fine when a server limits attempts (like an ATM), but useless for offline encryption, where the attacker can try as fast as their CPU allows. Legacy ZipCrypto is also weak. Use AES-256 (7-Zip) with a long passphrase.

### 15 — Wiretap (Network Forensics)

Wireshark filter `http.request.method == "POST"` shows three `POST /login` requests:

| Password sent | Response |
|---------------|----------|
| `Oasis%402025` (`Oasis@2025`) | `401 Unauthorized` |
| `admin123` | `401 Unauthorized` |
| `TAIBAH%7Bcl34rt3xt_http_l34ks_cr3ds%7D` | `302 Found` → `/dashboard` |

URL-decode the successful one: `TAIBAH{cl34rt3xt_http_l34ks_cr3ds}`. Command-line alternative:

```bash
tcpdump -nn -A -r capture.pcap | grep -E "password=|HTTP/1.1 [0-9]{3}"
```

**Lesson:** Anything sent over HTTP can be read by anyone on the network path. Use HTTPS everywhere, including internal sites.

### 16 — Pixel Secrets (Steganography)

The flag is stored in the least significant bit of each R, G, B value, row by row, MSB-first, and ends with a `0x00` byte. The PNG `tEXt` comment is a decoy ("Nice try!...").

```bash
zsteg dunes.png          # look for the b1,rgb line showing TAIBAH{...}
```

```python
from PIL import Image
img = Image.open("dunes.png").convert("RGB")
bits = "".join(str(v & 1) for v in img.tobytes())
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits), 8))
print(data.split(b"\0")[0])
```

**Lesson:** Steganography hides the *existence* of a message. Changing the lowest bit is invisible to the eye, but statistical tools detect it. Blue teams check images leaving the network for exactly this kind of exfiltration.

### 17 — Floodgate (Reverse Engineering)

The check (inlined into `main` by the compiler) decompiles to roughly:

```c
st = 0x5c;
for (i = 0; i < 31; i++) {
    st = st * 37 + 11;                     // may appear as lea tricks or 0x25 / 0xb
    diff |= ((input[i] ^ st) + 3 * i) ^ ENC[i];
}
```

`ENC` is a 31-byte array in `.rodata`. Invert each step:

```python
ENC = [...]   # copy the 31 bytes from Ghidra
st, flag = 0x5C, ""
for i, e in enumerate(ENC):
    st = (st * 37 + 11) & 0xFF
    flag += chr(((e - 3 * i) & 0xFF) ^ st)
print(flag)
```

**Anti-debugging:** `main` calls `ptrace(PTRACE_TRACEME)` first. Under `gdb`, `strace`, or `ltrace` the call fails and the program prints `Debugger detected.` Students who want to debug can patch the conditional jump after the call (or `set $rax = 0` in gdb after it returns). The intended solution is static, so no debugger is needed.

**Lesson:** Anything a program checks locally can be reversed. Stripping symbols and anti-debug tricks only slow an analyst down.

### 18 — Deleted but Not Forgotten (Forensics / Git)

```bash
tar -xzf oasis-portal.tar.gz && cd oasis-portal
git log --oneline
#  ... Add health check endpoint
#  ... Move secrets to environment variables
#  ... Add payment gateway integration      <- the leak
#  ... Initial commit
git log -p | grep -n TAIBAH
# or: git show HEAD~2:config.py
```

The latest version of `config.py` reads the key from `os.environ`, but the commit "Add payment gateway integration" still contains `PAYMENT_API_KEY = "TAIBAH{g1t_n3v3r_f0rg3ts_4_c0mm1t}"`.

**Lesson:** Git history is permanent. A leaked secret must be **rotated**. Removing it in a new commit doesn't help. Use `.gitignore`, environment variables, and pre-commit secret scanners (`gitleaks`, `trufflehog`).

### 19 — Onion Layers (Encoding)

Peel in this order: Base64 → Hex → Base32 → Zlib → ROT13.

```python
import base64, codecs, zlib
s = open("layers.txt").read().strip()
s = base64.b64decode(s)            # b'5044...'      (hex)
s = bytes.fromhex(s.decode())      # b'PDNHH5YL...=' (base32)
s = base64.b32decode(s)            # b'\x78\xda...'  (zlib magic)
s = zlib.decompress(s).decode()    # 'GNVONU{...}'   (rot13)
print(codecs.decode(s, "rot13"))
```

CyberChef recipe: **From Base64 → From Hex → From Base32 → Zlib Inflate → ROT13**.

**Lesson:** Stacking encodings adds no security. Each layer is recognizable by its alphabet or magic bytes. Analysts see this constantly in malware droppers and obfuscated scripts.

### 20 — Token of Trust (Web / Cryptography)

1. Decode the token at jwt.io. The header is `{"alg":"HS256","typ":"JWT"}` and the payload is a guest session.
2. Crack the HMAC secret with the leaked wordlist. The secret is **`mirage2025`**:
   ```bash
   hashcat -m 16500 token.txt wordlist.txt
   ```
3. `vault_tool.py` XORs data with `SHA-256(secret)`, so running it again decrypts:
   ```bash
   JWT_SECRET=mirage2025 python3 vault_tool.py vault.enc vault.txt && cat vault.txt
   ```

**Bonus discussion:** with the secret, students could also forge a token with `"role": "admin"`. Ask them why that is much worse than reading the vault.

**Lesson:** An HS256 JWT is only as strong as its secret, and anyone holding one token can brute-force the secret offline. Use long random secrets (or asymmetric RS256/EdDSA keys), and never reuse one secret for several purposes.
